아파트멘터리 OEM·ODM
공급망 관리 체계

그룹사 최초 OEM/ODM 착수 건. 맨땅에서 정리한 초기 아이데이션이며, 결론은 도표로, 근거·풀이는 하단 펼치기로 뒀습니다.

읽기 전 — 본 문서는 개편 정착 구조(담당자 발령 후) 기준입니다. 현재는 발령 전이라 슬로우베드사업팀이 고객사 소통·PM을 대행 중이며, 발령 후 해당 역할이 매트리스유통사업팀으로 이관됩니다. 문서의 "유통사업팀"은 이관 후 기준 표기입니다.
한눈에
  • 구조 — 아파트멘터리 = 내부 매트리스 + 외주 프레임 투트랙.
  • R&R — 고객 소통=유통사업팀 / 공급처 소통=procurement팀(외주)·유통사업팀(내부) / 개발=슬로우베드사업팀+연구소 / 품질=품질관리팀 / 수주 이후 계획·재고·납기=SCM.
  • 최상류 미결 — 코드 귀속 = 매출·재고 인식 = 정산이 한 덩어리로 막혀 있음. "슬로우베드가 팔지 않는 재고를 슬로우베드 재고로 잡는 게 맞나"가 핵심.
  • 리스크 — 프레임 외주가 JIT 거부 → 개런티 재고생산으로 재고 위험이 우리로 이전.
01 — 개념

용어

OEM / ODM
주문자 사양대로 제조(OEM) / 제조사가 개발·설계까지 하여 주문자 브랜드로 납품(ODM). 매트리스는 개발이 우리 안에 있어 ODM 성격.
3PL (레터스)
보관·운송·시공 대행. 맡아둘 뿐 소유하지 않음.
위탁 / 임가공
위탁 = 외주처가 자재조달·완제품 제작 후 우리가 매입 / 임가공 = 자재를 우리가 대주고 가공만. 프레임은 위탁(일부 사급).
JIT (오더베이스)
주문 후 생산·발주, 재고 미보유. 아파트멘터리의 요구 운영 방식.
02 — 배경

사업 배경

기존 외주 업체 납품 불가 → 슬로우베드에 OEM 요청, 개발 완료 상태에서 인프라·공급망 세팅 단계.

사업 성격
그룹사 내 OEM/ODM 판매 최초. 선례 없이 표준을 만드는 과제.
수량·리드타임
B2C 월 약 30세트(소량). 주문~시공 10일~2주. 고객사 JIT 요구.
코드 = 이동 게이트
코드 없이 실물 이동 불가. 수주 후 코드·ERP 등록 → OMS 연동 순.
원가·계약 변수
양지 입고 기준 원가 재산정. 표준 납품계약서 공유 대기(고객사 내부 검토 중).

코드 = 인식 = 정산

세 개가 사슬로 묶여 있어, 맨 앞(코드 귀속)이 안 정해지면 뒤가 다 막힙니다. SCM 단독 결정 불가.

07 — SCM 실행

인프라 세팅 체크리스트

SCM 영역이 규명됐으니 챙길 항목. 수주가 전체 트리거 — 코드부터 순차.

수주 트리거 · 순차
  • 단품코드 생성·ERP 등록 (그룹사 기준, 박스 단위) — 05 선행
  • WMS 연동용 코드 등록 (코드 없이 실물 이동 불가)
  • OMS 아이디 부여·레터스 연동 (코드 완료 후)
  • 아파트멘터리 OMS 접근 정의 (주문·재고·AS 조회, 대리점 수준)
상시 운영
  • 재고 가시성 — 출고+생산지 창고 합산 모니터링에 OEM 품목 편입
  • 납기 모니터링 — 투트랙 지연 조기 감지·대응
  • 개런티 재고 트래킹 — buffer·초과분 소진 관리
  • 품질→공급망 대응 플로우 — 품질관리팀 판정 ↔ SCM 소싱·납기 조정

부록 — 상세 설명 (필요 시)

이해 안 될 때 펼쳐보기

코드 = 인식 = 정산이 왜 한 덩어리인가

코드는 브랜드 단위로만 물립니다(회사=일룸 / 브랜드=슬로우베드). 슬로우베드 코드를 따는 순간 시스템이 자동으로 슬로우베드 브랜드 매출·재고로 인식하고, 정산도 그 브랜드 손익으로 흘러갑니다. 즉 코드 하나가 인식·정산을 다 끌고 갑니다.

문제는 "슬로우베드가 팔지 않는(고객사=아파트멘터리) 재고를 슬로우베드 재고로 잡는 게 회계적으로 맞나"입니다. 논리상 매트리스사업부(슬로우베드사업팀+매트리스유통사업팀) 귀속이 자연스러운데, 우리 구조는 사업부 ≈ 브랜드라 원래 구분이 없었습니다. 조직개편으로 사업부가 브랜드보다 커지면서 이 등식이 깨졌고, 그 틈에서 "어느 코드를 딸지"가 공백으로 남았습니다.

개런티 재고 — 왜 우리 위험이 되나

프레임 외주는 원래 위탁생산(업체 자재조달)이라 매입 전까지 업체 재고여야 합니다. 그런데 월 30개 소량이라 JIT 견적을 업체가 거부 → 월 개런티 수량 재고생산으로 전환. 이때 재고 위험이 업체 → 우리로 넘어옵니다.

  • 개런티가 매입 약정이면 입고 시점에 우리 재고. 고객 미인수 초과분 = 우리 보유.
  • 계상 시점은 양지 입고 기준과 연동 → 입고 전 업체 보유분은 아직 업체 것.
  • 월 수요(30) < 개런티면 buffer가 z-grade성 누적재고로 축적 → 소진 규칙 필요.
품질관리팀 vs SCM 경계

품질관리팀 — 품질 기준 수립, 입고 검사, 합불 판정, 품질 이슈 원인 판정, 업체 품질 감사.

SCM — 품질 이슈가 납기·재고에 미치는 영향만. 업체가 품질 문제로 못 대면 대체 소싱·재고 버퍼·납기 재조정. "업체 교체·추가개발" 판단(품질 사유)은 품질관리팀, 그 결과의 공급망 실행만 SCM.

외주까지 껴서 OEM/ODM 하는 목적 (A/B 가설)

procurement팀장 컨선의 본질은 "OEM/ODM인데 왜 내부 제조를 안 쓰고 외주(프레임)를 끼나"였습니다. 두 가설:

  • A. 인프라 수익화 — 우리 코드·물류·3PL 인프라를 외주 품목에도 얹어 관리 마진을 먹는 모델.
  • B. 통합 수주 방어 — 매트만으론 세트 수주를 못 따니 프레임까지 원소스로 묶어 고객사를 잡음.

어느 쪽이든 SCM의 실무 개입 범위는 동일합니다(달라지는 건 정산 층뿐). 따라서 이건 SCM 설계 변수가 아니라 "이 사업을 확장할 가치가 있나"라는 사업 판단 → 상급자·사업부 몫으로 남깁니다.
